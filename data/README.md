# data/

Two kinds of material live here, and the split decides what git tracks.

## Tracked: evidence and curated state

Everything the pipeline has *concluded* or a human has *reviewed*. None of it
can be regenerated byte-for-byte, so it is versioned like code.

| Path | What it is |
|---|---|
| `taxonomy/` | The canonical stage / geo / focus vocabularies. Single source of truth; `lib/taxonomy.ts` and ingest validation both read these files. |
| `aggregation/company-base/` | Per-investor portfolio company base with review status (`auto_confirmed`, …). Human-approved rows live here. |
| `aggregation/entities/` | Per-investor SEC vehicle lists. |
| `aggregation/investors/` | Ingest input rows plus per-field `*.sources.json` provenance sidecars. |
| `aggregation/outcomes/` | Outcome derivation runs, calibration answers, resolved decisions. |
| `aggregation/sources/edgar/`, `sources/wayback/`, `sources/site/`, `sources/unicorns/` | Extracted evidence snapshots that the sidecars cite. Small, and re-extraction is not deterministic (Wayback availability, site changes), so they are kept. |
| `export/` | Legacy seed exports. |

## Not tracked: bulk SEC source material

Verbatim SEC publications. Anyone can re-download them, and the SEC is a more
trustworthy host than this repo, so they are gitignored:

- `filings/form-d/` — quarterly Form D bulk ZIPs, 2008q1 onward (~190MB)
- `filings/edgar-headers/` — per-filing header cache, filled on demand by `scripts/edgar_common.py`
- `aggregation/sources/sec/cik-lookup-data.txt` — SEC CIK lookup table (~38MB)

After cloning, hydrate them with:

```bash
python3 scripts/fetch-filings.py
```

Re-running is idempotent and picks up the newest quarter only. The scripts
that need this material (`formd-query.py`, `build-company-base.py`,
`build-firm-profile.py`, …) fail with a clear path error if it is missing.

## Adding an investor

New per-investor material goes in the tracked directories above: base rows in
`aggregation/company-base/<slug>.json`, profile + sidecar via
`scripts/build-firm-profile.py <slug>`, ingest input in
`aggregation/investors/`. Keep bulk downloads out; if a new source class
arrives (another regulator's bulk data), extend `fetch-filings.py` and the
ignore list rather than committing the archive.

There is no per-investor derivation step. The investor-level metrics
(`track_record`, `graduation_rate`, and the three `company_*_distribution`
columns) are machine-owned: `recompute_investor_metrics` in the database
recomputes them from `public.companies` on every companies write, so
ingesting company rows (`scripts/ingest-companies.ts`) is what populates
them. The ingest payload must never carry these columns;
`scripts/ingest-investor.ts` fails loudly if it does.
